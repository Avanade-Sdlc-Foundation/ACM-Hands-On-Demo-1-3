# 演習 5: 技術的負債改善計画の作成

| [← 前の手順](./4-architecture-docs.md) | [README に戻る](./README.md) |
|:--|--:|

高度な技術的負債分析プロンプトを使用して、Spring Boot PetClinicプロジェクトの包括的な技術的負債評価と改善計画を作成します。この分析により、プロジェクトの品質向上と持続的な開発効率の改善を実現します。

## シナリオ

プロダクトオーナーから以下のような課題提起がありました：
- 開発速度が徐々に低下している
- バグ修正に予想以上の時間がかかる
- 新機能追加時の影響範囲が予測困難
- コードレビュー時間が増加傾向にある
- テストの実行時間が長くなっている

これらの問題の根本原因を特定し、体系的な改善計画を策定するため、GitHub Copilotの技術的負債分析機能を活用して、科学的で実行可能な改善ロードマップを作成します。

## ? 必須 1. 技術的負債分析の準備

### 1.1 新しい分析セッションの開始

1. Copilot Chatで新しいセッションを開始します
   - 「＋」アイコンまたは「New Session」をクリック
   ![New Session](images/new-session.png)
2. 前のセッションの分析結果に影響されないクリーンな環境を確保
3. プロジェクト全体の認識を確認します


## ? 必須 2. 包括的技術的負債分析の実行

### 2.1 メイン分析プロンプトの実行

Copilot Chatに以下のプロンプトを入力して実行します：

```
/tech-debt-remediation-plan

このSpring Boot PetClinicプロジェクトの技術的負債を分析し、改善計画を作成してください。

分析対象：
- コード品質（重複コード、複雑なメソッド、命名規則）
- アーキテクチャ負債（レイヤー違反、依存関係の問題）
- セキュリティ脆弱性
- パフォーマンス課題
- テストカバレッジと品質
- ドキュメント不足
- 依存関係の古さや脆弱性

優先度付けと実装ロードマップも含めてください。
```

### 2.2 分析プロセスの観察

1. Copilotが以下の分析を順次実行していることを確認：
   - 静的コード解析
   - アーキテクチャパターン評価
   - 依存関係グラフ分析
   - テスト品質評価
   - セキュリティ脆弱性スキャン

2. 分析の完了まで数分かかる場合があります（詳細分析のため）

## ? 必須 3. ブループリントプロンプトの特色体験

### 3.1 自動的な包括分析の確認

生成された技術的負債レポートで以下の **自動分析機能** を体験します：

1. **多角的な分析視点**  
   - コード品質、アーキテクチャ、セキュリティ、パフォーマンスが一度に分析
   - 手動チェックでは見落としがちな問題も自動検出

2. **構造化された結果表示**  
   - 問題が優先度別・カテゴリ別に整理されて提示
   - 単なる問題列挙ではなく、改善への道筋も含む

### 3.2 実行可能なロードマップ生成の確認

**ブループリントプロンプトの最大の特色:**
- 問題特定だけでなく **実装計画まで自動生成**
- 優先度マトリクス（影響度×実装コスト）による合理的な計画
- フェーズ分けされた現実的な改善ロードマップ

**確認ポイント:**
```
生成されたレポートに以下が含まれているか確認：
? 優先度付きの改善項目リスト
? 実装工数の見積もり
? 段階的な実施計画（フェーズ1?3）
? 各改善項目の期待効果
```

## ? 参考 4. 他手法との違いを実感

**従来の手動分析 vs ブループリントプロンプト:**

| 従来手法 | ブループリントプロンプト |
|----------|------------------------|
| 問題リストの羅列 | **優先度付き改善ロードマップ** |
| 主観的な判断 | **定量的な影響度評価** |
| 分散的な分析 | **包括的な一括分析** |

**体験のポイント：**
生成されたレポートで「なぜこの改善が優先されるのか」の根拠が明記されているかを確認してください。

## ? 必須 5. 実行可能な改善計画の確認

### 5.1 ブループリントの特色：自動的な実行計画生成

**確認項目：**
```
生成されたレポートに以下が含まれているか確認：
? 優先度マトリクス（影響度×実装コスト）
? 3段階の実施フェーズ分け
? 各改善項目の具体的な実装手順
? 期待される改善効果の定量化
```

**なぜこれが重要か：**
単なる問題指摘ではなく、**実装可能な改善計画まで自動生成**されることで、チームが即座にアクションを開始できます。

## ? オプション 6. さらなる分析の追加

より詳細な分析が必要な場合、以下の追加プロンプトを実行：

```
以下の観点からも追加分析を実行してください：
- CI/CDパイプラインの改善点
- 開発者体験（DX）の向上策
- 運用監視とログ改善
```


## ?? トラブルシューティング

### 問題が発生した場合

1. **技術的負債プロンプトが認識されない場合**
   - `/tech-debt-remediation-plan` コマンドの正確性確認
   - Copilot拡張機能の最新版確認
   - 新しいセッションでの再実行

2. **分析が表面的な場合**
   - 特定の課題領域に焦点を絞った追加分析
   - コードベースの特定部分での詳細分析の要求

3. **改善提案が一般的すぎる場合**
   - プロジェクト固有の制約条件を明示
   - 詳細なコンテキスト情報の提供

### 分析精度の向上

より精密な分析のために：
```
以下の特定の問題領域に焦点を当てて詳細分析を実行してください：
[具体的な問題領域を指定]
```

## まとめと継続的改善

この演習で以下を実現しました：

- **包括的技術的負債の可視化**
- **科学的根拠に基づいた課題特定**
- **実行可能性を考慮した改善計画策定**
- **優先度付きロードマップの作成**

**継続的改善のための活用方法:**

1. **定期的な技術的負債の計測**
   - 四半期毎の再分析実行
   - 改善進捗の定量的評価

2. **チーム内での改善文化醸成**
   - 改善計画の共有と討議
   - 個人レベルでの品質意識向上

3. **ステークホルダーとの合意形成**
   - 技術的投資の必要性説明
   - ROIの明確化と承認取得

**次のアクションアイテム:**
- 生成された改善計画の詳細レビュー
- チームでの改善優先度の合意形成
- 第1フェーズ改善項目の実装開始
- 改善効果の測定体制整備

この技術的負債分析により、Spring Boot PetClinicプロジェクトの持続的な品質向上と開発効率の改善が実現できます。
