# 演習 3: 2つの指示ファイルの比較と分析

| [← 前の手順](./2-blueprint-instructions.md) | [次の手順: アーキテクチャドキュメント生成 →](./4-architecture-docs.md) |

前の2つの演習で作成した指示ファイル（Agent生成とブループリント生成）を詳細に比較分析し、それぞれの特徴と適用場面を理解します。この比較により、プロジェクトの状況に応じた最適なアプローチを選択できるようになります。

## シナリオ

開発チームリーダーとして、2つの異なる手法で生成されたカスタム指示ファイルを評価し、どちらがプロジェクトに最適かを判断する必要があります。また、新しいチームメンバーのオンボーディングや既存メンバーのコード品質向上により効果的な指示ファイルを選定し、その理由を明確にする必要があります。

## 必須 1. ファイル比較の準備

### 1.1 生成ファイルの確認

1. 以下の2つのファイルが存在することを確認します：
   - `.github/agent-copilot-instructions.md` (演習1で作成)
   - `.github/prompt-copilot-instructions.md` (演習2で作成)

2. ファイルが存在しない場合の確認手順：
   ```bash
   # VS Codeのターミナルで実行
   ls -la .github/*.md
   ```
   または、VS Codeのエクスプローラーで`.github`フォルダを確認してください。

3. 両ファイルをVS Codeで並べて開きます
3. 内容の差異を視覚的に確認します

### 1.2 比較環境の準備

1. VS Codeの分割ビュー機能を使用します：
   - `View` > `Editor Layout` > `Split Right`
2. 左右のペインに異なるファイルを配置します
3. スクロール同期を有効にしてファイル内容を比較しやすくします

## 必須 2. 構成要素別比較分析

---
### 2. 比較の観点

2つの指示ファイルを「どんな人に向いているか」「どんな場面で役立つか」という観点で、比較してください。

#### 2.1 技術内容の分かりやすさ

- **Agent生成**: プログラムの基本的な使い方や、よく使う道具（例：Spring BootやJavaなど）をざっくり紹介しています。初心者でも「このプロジェクトは何を使っているのか」がすぐ分かります。
- **ブループリント生成**: 使っている道具のバージョンや、どんな細かい機能を使っているかまで詳しく説明しています。経験者が「このプロジェクトの特徴は何か」を知るのに役立ちます。

#### 2.2 ルールやお作法の具体性

- **Agent生成**: 「こういうルールで書きましょう」といった一般的な決まりごとを説明しています。たとえば「コントローラーにはビジネスロジックを書かない」など、広く使われるルールが中心です。
- **ブループリント生成**: 実際のプロジェクトで使われている具体的な書き方や例を紹介しています。「このクラスにはこういう書き方をしている」など、現場で役立つ細かいルールが載っています。

#### 2.3 コード例の分かりやすさ

- **Agent生成**: 教科書に載っているようなシンプルな例が多いです。
   ```java
   // 一般的な例
   @Controller
   public class SampleController {
      // 基本的なパターン例
   }
   ```
- **ブループリント生成**: 実際のプロジェクトで使われている本物のコード例が載っています。
   ```java
   // プロジェクト固有の実例
   public class Owner extends Person {
      @OneToMany(cascade = CascadeType.ALL, mappedBy = "owner")
      private Set<Pet> pets;
      // ToStringCreatorパターンの実装例
   }
   ```

#### 2.4 どんな人・どんな場面に向いているか

- **Agent生成**: プログラミングやSpring Bootに慣れていない人、これから学びたい人におすすめです。基本を押さえたいときに役立ちます。
- **ブループリント生成**: すでにプロジェクトに詳しい人や、実際の現場で「どう書かれているか」を知りたい人に向いています。より実践的な内容です。

## 参考 3. 実用性評価

### 3.1 新規開発時の有用性評価

以下の観点で両ファイルを評価します：

1. **即座に適用可能な情報の有無**
   - Agent生成: 基本的なガイドライン提供
   - ブループリント生成: 実装可能な具体例提供

2. **学習コストの評価**
   - Agent生成: Spring Boot初心者にも理解しやすい
   - ブループリント生成: プロジェクト経験者により有用

### 3.2 コード品質向上への貢献度

1. **禁止事項の具体性**
   - Agent生成: 「Controller層でのビジネスロジック実装を避ける」
   - ブループリント生成: 「Controller層での@Transactional使用禁止」

2. **ベストプラクティスの詳細度**
   - Agent生成: 一般的なSpring推奨事項
   - ブループリント生成: プロジェクト固有の実装パターン

## 参考 4. 詳細な品質分析

### 4.1 検出されたパターンの深度比較

**Agent生成で検出されたパターン:**
- レイヤードアーキテクチャの基本概念
- Spring Bootの標準的な使用方法
- 一般的なJPAのベストプラクティス

**ブループリント生成で検出されたパターン:**
- `BaseEntity` → `NamedEntity` → `Person` の継承チェーン
- `ToStringCreator`の具体的使用方法
- プロジェクト固有のBean Validationパターン
- 実際のRepository実装パターン

### 4.2 エラーパターンと回避策の比較

**Agent生成のアプローチ:**
- 一般的なアンチパターンの列挙
- 理論的な回避策の提示

**ブループリント生成のアプローチ:**
- プロジェクト実装から抽出した具体的な問題パターン
- 実際のコード修正例の提示

## オプション 5. 適用場面別の推奨手法

### 5.1 プロジェクト段階別の選択指針

**プロジェクト初期段階:**
- Agent生成が適：基本的な構造理解が重要
- 学習コスト低、即座に開始可能

**プロジェクト成熟段階:**
- ブループリント生成が適：詳細な実装ガイドが必要
- 品質向上と一貫性確保に貢献

### 5.2 チーム構成別の選択指針

**Spring Boot初心者中心のチーム:**
```markdown
Agent生成を推奨
- 理解しやすい概念的説明
- 段階的な学習が可能
```

**経験豊富な開発者中心のチーム:**
```markdown
ブループリント生成を推奨
- 即座に活用可能な実装例
- 高品質コードの維持に貢献
```

## トラブルシューティング

### 比較分析での注意点

1. **内容の偏りがある場合の対処**
   - 両方のファイルが同じプロジェクトから生成されていることを確認
   - 生成時のプロンプト内容が適切だったかを検証

2. **目的に応じた評価観点の調整**
   - チームのスキルレベルを考慮した評価
   - プロジェクトの要求品質レベルに応じた重要度設定

### 評価の客観性確保

以下の定量的指標も参考にします：
- コード例の数量差
- 具体的な実装指示の詳細度
- プロジェクト固有パターンの検出率

## まとめと次のステップ

この比較分析により以下のことが明確になりました：

**Agent生成の特徴:**
- 概念理解と学習に適している
- プロジェクト初期やSpring Boot初心者に有効
- 広範囲な基礎知識を体系的に提供

**ブループリント生成の特徴:**
- 実践的で即座に活用可能
- プロジェクト固有の詳細なガイダンス提供  
- 経験者の生産性向上に直結

**推奨する活用戦略:**
1. プロジェクト初期：Agent生成で基盤作り
2. 開発本格化：ブループリント生成で詳細化
3. チーム教育：両方を組み合わせた段階的指導

次のステップでは、この知見を活かして、カスタムプロンプトを使用したアーキテクチャドキュメントの生成を実践します。プロジェクトの包括的な技術文書を作成し、チーム全体の理解向上を図ります。
